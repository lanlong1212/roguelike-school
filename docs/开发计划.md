# 《迷城棋局》 MVP 开发计划

> 基于 [labyrinth-chess-mvp-v1.0-prd.md](./prds/labyrinth-chess-mvp-v1.0-prd.md) 生成
> 周期：9 天 | 目标：可运行 MVP Demo，tag `v0.1.0-mvp`

---

## 总览

```
Day 1: 核心框架   →  Day 2-3: 地图与探索  →  Day 4-6: 战斗与AI
Day 7: 物品系统   →  Day 8: UI与流程串联  →  Day 9: 联调测试
```

**核心原则：**
- 每天产出一个**可运行验证**的里程碑，不做"攒一周再跑"
- 模块依赖从底层往上：`utils` → `core` → `world`/`entities` → `combat`/`ai` → `items` → `ui` → `states` → `main`
- 每天结束前 `git commit`，每天开始前确认上一天的成果可运行

---

## 模块依赖关系

```
utils ──→ core ──→ states
  │         │        ↑
  │         ↓        │
  └──→ world ──→ play_state
  │         ↑
  └──→ entities ──→ combat ──→ ai
              ↑         ↑
              └──→ items ─┘
                          ↑
                          │
                        ui ──→ play_state/pause_state/game_over_state
```

## 风险与应对

| 风险 | 应对 |
|------|------|
| BSP 生成出现房间重叠/走廊断裂 | Day 2 编写生成验证测试，失败重试 |
| AI 行为树 tick 超时（>16ms） | 限制每回合 AI 决策深度，避免全图搜索 |
| 9 天时间紧 | 严格按里程碑交付，超时功能降级到第二阶段 |
| pygame-ce 版本兼容问题 | 锁定 2.5.7，不随意升级 |
| 数值不平衡导致通关过快/过慢 | Day 9 集中调整，预留数值配置表方便热改 |

## 开发节奏

| 时段 | 活动 |
|------|------|
| 每天**开始前** | `git pull`，跑一遍昨天成果确认无回归 |
| 每天**编码中** | 小步快跑，每完成一个子任务就 `python src/main.py` 验证 |
| 每天**结束前** | `git add .` → `git commit -m "Day N: ..."` → `git push` |
