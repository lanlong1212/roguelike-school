## 需求描述

### 背景

- **业务问题**：Roguelike + 网格战棋品类尚无头部标杆产品，市场存在空白；回合制策略天然适配 PC 与移动端，独立游戏分发渠道成熟。
- **目标用户**：硬核策略玩家（22-35岁）、Roguelike 爱好者（18-30岁）、休闲策略玩家（25-40岁）。
- **价值主张**：以网格战棋替代纯卡牌对战，增加空间位置/地形/障碍策略维度；AI 行为树让敌人更智能动态；元素反应 + 技能 + 天赋多维组合提供丰富 Build 构筑。

### 功能概述

- **核心功能**：程序化地牢生成（3 层）、回合制网格战斗、AI 行为树敌人（4 种）、元素反应系统、装备药水、锁房机制、永久死亡。
- **功能边界（已实现）**：
  - **包括**：3 层各 6 房间完整流程、1 个可玩角色（6 技能 + 3 天赋）、4 种敌人（2 基础 + 1 精英 + 1 Boss）、装备与药水、元素反应、锁房、永久死亡与结算、数值平衡模拟器。
  - **不包括（后续阶段）**：多角色、遗物/防具/饰品、物品合成、套装效果、协同 AI、适应性 AI、隐藏房间、成就系统、图鉴、教程系统、多语言、模组支持、音效音乐、局外成长。
- **用户场景**：玩家从主菜单开局 → 程序化生成地牢 → 探索房间 → 回合制战斗 → 击败每层 Boss 下楼 → 通关/死亡 → 结算 → 回主菜单，单局 15-25 分钟。

### 详细需求

- **输入/输出**：
  - 输入：键盘（WASD/方向键移动、1-6 切换技能、M 移动模式、H 喝药、B 背包、V 收起 HUD、空格结束回合、Esc 暂停）+ 鼠标（左键选择/攻击/确认）。
  - 输出：1280×720 窗口画面、HUD 实时状态（HP/AP/状态图标）、战斗反馈（伤害飘字、网格高亮、回合提示）。
- **用户交互**：战斗回合状态机如下：
  ```
  玩家回合开始 → AP 重置（5点） → [选择行动]
                            ├→ 移动（消耗 1 AP，一次最多 3 格）
                            ├→ 攻击（消耗 AP，选目标）
                            ├→ 技能（消耗 AP，选目标/范围）
                            ├→ 使用道具（消耗 1 AP，H 键）
                            └→ 手动结束回合（空格；AP 耗尽不自动结束）→ 敌人回合 → AI 执行 → 回到玩家回合
  ```
  不支持行动撤销。
- **数据需求**：存档为 JSON 格式，存于 `./saves/`（打包版存 exe 旁），单存档槽。只存档**基础攻击力**（防武器加成在读档时翻倍）；局内（玩家位置、楼层、HP/AP、背包、已学技能）。
- **边界情况**：玩家死亡 → 等敌人攻击动画播完 → 结算界面 → 清空局内存档；战斗/精英/Boss 房开战后锁定，全灭才能离开；AP 耗尽时提示"AP已耗尽"，玩家手动结束回合。

## 一、 项目概述 (Project Overview)

**1. 游戏名称：**
《迷城棋局》（Labyrinth Chess）

**2. 游戏类型：**
Roguelike + 回合制策略战棋（Turn-based Tactical Roguelike）

**3. 开发平台：**
PC（Windows），技术栈 Python 3.13 + pygame-ce 2.5.7

**4. 开发周期：**
分四阶段推进，第一阶段（9 天 MVP）已完成并超出原范围

**5. 游戏总览：**
《迷城棋局》是一款俯视角网格战棋 Roguelike 游戏。玩家在程序化生成的多层地牢中，以回合制方式操控角色在网格上移动、攻击、释放技能，通过技能、天赋、装备、元素反应的组合构筑独特 Build，挑战由行为树驱动的智能敌人，最终击败每层 Boss。永久死亡机制保证每局体验独一无二。

**核心标签：** 回合制 · 网格战棋 · 程序化生成 · AI 行为树 · 元素反应 · 永久死亡

## 二、 市场与用户分析 (Market Analysis)

**1. 目标受众：**

- **硬核策略玩家（22-35岁）：** 追求深度策略性、高难度挑战和 Build 多样性，每周 15-25 小时，代表游戏偏好《杀戮尖塔》《暗黑地牢》《Into the Breach》。
- **Roguelike 爱好者（18-30岁）：** 享受随机性、收藏解锁和戏剧性场面，每周 10-20 小时，代表游戏偏好《以撒的结合》《挺进地牢》《哈迪斯》。
- **休闲策略玩家（25-40岁）：** 碎片化时间可玩、节奏可控、需要随时暂停，每周 5-10 小时，代表游戏偏好《文明》《火焰纹章》《XCOM》。

**2. 竞品分析：**

| 竞品名称 | 优点 | 缺点 | 本作差异化策略 |
| :--- | :--- | :--- | :--- |
| 《杀戮尖塔》 | 卡牌 Build 深度极高，进阶难度系统成熟，销量 500万+ | 纯卡牌缺乏空间位置策略，战斗节奏单一 | 以 **网格战棋** 替代卡牌对战，增加空间位置/地形/朝向策略维度 |
| 《暗黑地牢》 | 压力系统创新，哥特美术氛围浓厚，队伍管理有深度 | 节奏偏慢，RNG 失误惩罚过重 | 引入 **AI 行为树** 让敌人更智能动态，降低纯运气导致的负面体验 |
| 《Into the Breach》 | 每一步都是完美信息解谜，策略纯度极高 | 内容量偏少，Build 多样性不足 | 保留网格战棋深度，叠加 **元素反应+技能+天赋** 的丰富 Build 构筑 |

**市场机会：** Roguelike + 网格战棋品类尚未出现头部标杆产品，市场存在明显空白；回合制天然适配 PC 与移动端，独立游戏分发渠道成熟。

## 三、 核心概念与设计 (Core Concept & Design)

**1. 故事背景（世界观）：**

迷城是一座由古代文明建造的永不停息的棋盘迷宫，每隔百年会召唤一名"棋手"进入其中。玩家扮演被选中的棋手，必须在程序化生成的层层地牢中击败守关的棋灵，最终抵达迷城核心揭开永动之谜。每一局都是平行时空中的一次尝试——死亡后记忆清零，但迷城会记住棋手的成长。（世界观暂未在游戏内以剧情呈现「未实现，规划中」）

**2. 核心玩法（游戏循环）：**

- **探索（随机生成）：** 程序化生成 3 层地牢，每层 6 个房间（1 Boss + 1 精英 + 1 商店 + 1 休息 + 2 战斗），自由探索，战争迷雾遮蔽未探索区域。战斗/精英/Boss 房开战即**锁房**。
- **战斗（回合制战棋）：** 网格地图上回合制对抗，每回合 5 点 AP，移动花 1 AP（上限 3 格），技能按消耗表扣 AP。伤害基于攻防公式 + 暴击 + 元素反应计算，障碍柱可挡路/挡远程视线。
- **构筑（Build）：** 通过技能（6 种）、天赋（3 种）、武器（铁剑/长弓）、药水、元素反应连招组合流派。遗物/防具/饰品/技能树「未实现，规划中」。
- **死亡与成长：** 局内永久死亡，进度清零；局外全局货币解锁「未实现，规划中」。

**3. 美术风格：**

- **基调：** 暗黑奇幻像素风格，带有棋盘/几何纹样的视觉符号，呼应"棋局"主题。
- **色彩：** 主色调为深紫/暗蓝的地下城氛围；角色/敌人/技能均有独立像素素材，特效（Boss AOE、元素飘字）用高饱和色突出。
- **视角：** 俯视角 2D 网格，瓦片尺寸 32×32 像素，相机跟随玩家。楼层主题色切换「未实现，规划中」。

**4. 游戏差异化创新：**

- **差异化1 — 空间战术维度：** 网格战棋引入位置、障碍柱（挡路+挡视线）等空间要素，每一步移动都是策略决策。
- **差异化2 — AI 行为树驱动：** Boss 多阶段切换、精英召唤+狂暴、骷髅远程风筝。
- **差异化3 — 元素反应连招：** 6 种元素反应（蒸发/冻结/感电/超导/融化/超载），形成"挂元素 → 触发反应"的连招循环。

## 四、 游戏子系统设计 (Game Subsystems)

**1. 技能子系统（已实现）：**

当前 1 个角色，共 6 个主动技能 + 3 个被动天赋：

| 技能 | AP | 射程 | 倍率 | 元素 | 效果 |
|------|----|----|------|------|------|
| 基础攻击 | 2 | 1 格 | 1.0× | 物理 | 初始自带 |
| 冲锋斩 | 3 | 1 格 | 1.8× | 物理 | 近战爆发 |
| 火球术 | 3 | 5 格 | 1.8× | 火 | 3×3 溅射 |
| 寒冰箭 | 3 | 4 格 | 1.6× | 冰 | 命中减速 1 回合 |
| 水弹 | 2 | 3 格 | 1.2× | 水 | 便宜挂水 |
| 雷击 | 3 | 4 格 | 1.7× | 雷 | 直线穿透 |

- 初始只拥有「基础攻击」，其余技能在休息房"强化"三选一学习
- 被动天赋（休息房三选一，永久生效）：生命增幅（HP+10%）、精力充沛（AP+1）、轻步疾行（移动+1）
- **元素反应系统（已实现）：** 蒸发(火+水 ×1.5)、冻结(冰+水 跳过回合)、感电(雷+水 受击×1.5)、超导(雷+冰 破甲)、融化(火+冰 受击×1.25)、超载(雷+火 延迟爆炸)；附着持续 2 回合
- 组合技、符文/铭文系统「未实现，规划中」

**2. 物品/道具系统（部分实现）：**

- **装备（已实现）：** 铁剑（ATK+2，20 金币）、长弓（普攻射程提升，35 金币）；防具/饰品/随机词缀/稀有度「未实现，规划中」
- **遗物/神器：「未实现，规划中」**
- **消耗品（已实现）：** 恢复药水（回复 15 HP，10 金币）、力量药水（本场战斗 ATK+2，25 金币）
- **背包（已实现）：** 物品格 + 武器装备槽，B 键打开，右上角关闭按钮
- 物品合成、套装效果「未实现，规划中」

**3. 地牢生成系统（核心，已实现·改版）：**

- **算法：** **等分网格布局**（原 BSP 已废弃）：地图 40×40，2 列 × 3 行，共 6 个固定尺寸房间
- **房间尺寸：** 固定 10×8 瓦片，直线走廊直连 + 环路保证连通
- **障碍：** 战斗/精英/Boss 房随机放置 6~10 根障碍柱（挡路 + 挡远程视线）
- **MVP 楼层：** 3 层，每层 6 个房间（1 Boss + 1 精英 + 1 商店 + 1 休息 + 2 战斗）
- **战争迷雾（已实现）：** 未探索不可见，已探索半透明显示；视线 Bresenham 检测
- **锁房（已实现）：** 战斗/精英/Boss 房开战锁定，全灭才解锁
- **随机种子：** 生成内部支持 seed 参数（可复现），UI 未暴露种子输入「未实现，规划中」
- 宝箱房、事件房、隐藏房间「未实现，规划中」

**4. 怪物/敌人系统（核心，已实现）：**

4 种敌人，由 AI 行为树驱动：

| 敌人 | HP/ATK/DEF | 行为 |
|------|-----------|------|
| 史莱姆 | 8 / 3 / 1 | 近战贴脸，移动 2，金币 3 |
| 骷髅 | 12 / 4 / 1 | 远程风筝，保持距离射击，金币 5 |
| 精英 | 20 / 5 / 2 | 阶段1 远程消耗 → 血量70%召唤史莱姆 → 血量40%狂暴连击，金币 10 |
| Boss | 80 / 8 / 3 | 阶段1 普攻 → 阶段2 连击 → 血量40%全屏震击（AOE 半径 3 / 7×7 + 粒子），金币 20 |

- 楼层缩放：每层敌人 HP/ATK ×1.2；L2 起战斗房 3 敌人（1 史莱姆 + 2 骷髅）
- 协同 AI、适应性 AI「未实现，规划中」

**5. 城镇/NPC系统：**

本作无城镇系统，以 **休息房** 替代（已实现）：每次进入可在「休息（回复 50% 最大 HP）」或「强化（三选一学技能/天赋）」中二选一，每房间限用一次。商店房（已实现）：铁剑 20、长弓 35、恢复药水 10、力量药水 25，每层可购买一次。

**6. 局外成长系统：「未实现，规划中」**

- 全局货币（记忆碎片）、解锁系统、难度解锁均未开发；永久死亡已实现

**7. 数值与平衡管理（已实现）：**

- **属性体系：** HP / ATK / DEF / 暴击率(10%) / 暴击伤害(1.5×) / AP上限(5) / 移动力(3) / 元素抗性
- **伤害公式：** `max(1, int(ATK × 倍率 − DEF × 0.5))` → 暴击 ×1.5 → 元素抗性 → 反应倍率/追加 → 感电/融化增伤 → 护盾吸收
- **MVP 数值基线（当前实现）：**

| 属性 | 玩家初始值 | 史莱姆 | 骷髅 | 精英 | Boss |
|------|----------|--------|------|------|------|
| HP | 20 | 8 | 12 | 20 | 80 |
| ATK | 6 | 3 | 4 | 5 | 8 |
| DEF | 2 | 1 | 1 | 2 | 3 |
| AP | 5 | 3 | 3 | 4 | 4 |
| 移动 | 3 | 2 | 2 | 3 | 2 |

- 暴击率：基础 10%，暴击伤害 1.5×；难度曲线：每层 ×1.2（非原 30%）
- 平衡验证：无头蒙特卡洛模拟器 `tests/balance_sim.py`（真实地形/AI/伤害公式），每场景 200 场

**8. 任务与成就子系统：「未实现，规划中」**

## 设计决策

### 技术方案

- **架构选择：** 状态机驱动的主循环 + 模块化包结构（`core/world/entities/combat/ai/items/ui/states/utils`），模块依赖从底层往上单向流动。
- **关键组件：**
  - `core/game.py`：主循环 + 状态栈管理
  - `world/dungeon_generator.py`：**等分网格地图生成**（原 BSP 已废弃，改为 2×3 网格 + 固定 10×8 房间 + 直线走廊环路）
  - `combat/battle_manager.py`：回合制战斗状态机
  - `combat/damage.py` + `combat/element.py`：伤害公式 + 元素附着/反应
  - `ai/behavior_tree.py`：行为树框架（Selector/Sequence/Condition/Action 节点）
  - `entities/`：实体系统（Entity 基类 → Player/Enemy 子类）
- **数据存储：** JSON 格式存档，`./saves/` 目录，单存档槽；只存基础攻击力（防武器加成翻倍）；打包版存 exe 旁
- **接口设计：** 模块间通过 Python import 通信，无外部 API；状态间通过 `game.push_state()`/`game.pop_state()` 切换（pop 不重进上一状态，防地图重置）
- **资源加载：** `asset_manager.py` 统一加载/缓存，支持目录帧序列与横向帧表；`resource_root()` 兼容开发与 PyInstaller 打包环境

### 约束条件

- **性能要求：** 目标 60 FPS，下限 30 FPS；地图生成 < 100ms；AI tick < 16ms
- **兼容性：** Windows 10/11，Python 3.10+，pygame-ce 2.5.7
- **分辨率：** 1280×720 窗口模式
- **相机：** 跟随玩家，坐标钳制防黑边
- **可扩展性：** 模块化设计支持后续阶段增量添加

### 风险评估

- **技术风险：** 原 BSP 房间重叠/走廊断裂风险 → **已消除**（改为等分网格布局，天然无重叠，全图连通有环路兜底）；AI tick 超时 → 每回合决策深度受限
- **依赖风险：** pygame-ce 社区维护，版本更新可能引入兼容问题 → 锁定 2.5.7
- **数值风险：** 数值不平衡 → 已建立 `tests/balance_sim.py` 蒙特卡洛模拟器 + 28 个单元测试持续验证
