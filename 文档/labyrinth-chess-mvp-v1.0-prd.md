# 《迷城棋局》 MVP - 产品需求文档 (PRD)

## 需求描述

### 背景

- **业务问题**：Roguelike + 网格战棋品类尚无头部标杆产品，市场存在空白；回合制策略天然适配 PC 与移动端，独立游戏分发渠道成熟。
- **目标用户**：硬核策略玩家（22-35岁）、Roguelike 爱好者（18-30岁）、休闲策略玩家（25-40岁）。
- **价值主张**：以网格战棋替代纯卡牌对战，增加空间位置/地形/朝向策略维度；AI 行为树让敌人更智能动态；装备+遗物+技能树多维组合提供丰富 Build 构筑。

### 功能概述

- **核心功能**：程序化地牢生成、回合制网格战斗、AI 行为树敌人、物品装备系统、永久死亡与局外成长。
- **功能边界**：
  - **包括**：1 层 6 房间完整流程、1 个可玩角色、2 基础敌人+1 精英+1 Boss、基础装备与药水、永久死亡与结算。
  - **不包括（MVP）**：多角色、多楼层、元素系统、物品合成、套装效果、协同 AI、适应性 AI、隐藏房间、成就系统、图鉴、教程系统、多语言、模组支持。
- **用户场景**：玩家从主菜单开局 → 程序化生成地牢 → 探索房间 → 回合制战斗 → 击败 Boss → 结算 → 回主菜单，单局 15-25 分钟。

### 详细需求

- **输入/输出**：
  - 输入：键盘（WASD/方向键移动、1-5 道具、Q/E 技能、空格结束回合、Tab 背包、C 角色面板、Esc 暂停）+ 鼠标（左键选择/确认、右键取消/查看）。
  - 输出：1280×720 窗口画面、HUD 实时状态、战斗反馈（伤害飘字、网格高亮、回合切换提示）。
- **用户交互**：战斗回合状态机如下：
  ```
  玩家回合开始 → AP 重置（5点） → [选择行动]
                            ├→ 移动（消耗 AP，上限3格/回合）
                            ├→ 攻击（消耗 AP，选目标）
                            ├→ 技能（消耗 AP，选目标/范围）
                            ├→ 使用道具（消耗 AP）
                            └→ 结束回合 → 敌人回合开始 → AI 执行 → 回到玩家回合
  ```
  不支持行动撤销。
- **数据需求**：存档为 JSON 格式，存于 `./saves/`，单存档槽。局内存档（玩家位置、已探索房间、HP/AP、背包），局外存档（全局货币、解锁状态）。
- **边界情况**：玩家死亡→结算界面→清空局内存档；游戏崩溃→重启从最近自动存档恢复；背包满→拾取前提示替换。

## 一、 项目概述 (Project Overview)

**1. 游戏名称：**
《迷城棋局》（Labyrinth Chess）

**2. 游戏类型：**
Roguelike + 回合制策略战棋（Turn-based Tactical Roguelike）

**3. 开发平台：**
PC（Windows），技术栈 Python + pygame-ce 2.5.7

**4. 开发周期：**
分四阶段推进，第一阶段 9 天产出核心 Demo（MVP）

**5. 游戏总览：**
《迷城棋局》是一款俯视角网格战棋 Roguelike 游戏。玩家在程序化生成的多层地牢中，以回合制方式操控角色在网格上移动、攻击、释放技能，通过装备、遗物、技能树的组合构筑独特 Build，挑战由行为树驱动的智能敌人，最终击败每层 Boss。永久死亡机制保证每局体验独一无二，局外解锁系统提供长期成长目标。

**核心标签：** 回合制 · 网格战棋 · 程序化生成 · AI 行为树 · Build 构筑 · 永久死亡

## 二、 市场与用户分析 (Market Analysis)

**1. 目标受众：**

- **硬核策略玩家（22-35岁）：** 追求深度策略性、高难度挑战和 Build 多样性，每周 15-25 小时，代表游戏偏好《杀戮尖塔》《暗黑地牢》《Into the Breach》。
- **Roguelike 爱好者（18-30岁）：** 享受随机性、收藏解锁和戏剧性场面，每周 10-20 小时，代表游戏偏好《以撒的结合》《挺进地牢》《哈迪斯》。
- **休闲策略玩家（25-40岁）：** 碎片化时间可玩、节奏可控、需要随时暂停，每周 5-10 小时，代表游戏偏好《文明》《火焰纹章》《XCOM》。

**2. 竞品分析：**

| 竞品名称 | 优点 | 缺点 | 本作差异化策略 |
| :--- | :--- | :--- | :--- |
| 《杀戮尖塔》 | 卡牌 Build 深度极高，进阶难度系统成熟，销量 500万+ | 纯卡牌缺乏空间位置策略，战斗节奏单一 | 以 **网格战棋** 替代卡牌对战，增加空间位置/地形/朝向策略维度 |
| 《暗黑地牢》 | 压力系统创新，哥特美术氛围浓厚，队伍管理有深度 | 节奏偏慢，RNG 失误惩罚过重 | 引入 **AI 行为树** 让敌人更智能动态，降低纯运气导致的负面体验 |
| 《Into the Breach》 | 每一步都是完美信息解谜，策略纯度极高 | 内容量偏少，Build 多样性不足 | 保留网格战棋深度，叠加 **装备+遗物+技能树** 的丰富 Build 构筑 |

**市场机会：** Roguelike + 网格战棋品类尚未出现头部标杆产品，市场存在明显空白；回合制天然适配 PC 与移动端，独立游戏分发渠道成熟。

## 三、 核心概念与设计 (Core Concept & Design)

**1. 故事背景（世界观）：**

迷城是一座由古代文明建造的永不停息的棋盘迷宫，每隔百年会召唤一名"棋手"进入其中。玩家扮演被选中的棋手，必须在程序化生成的层层地牢中击败守关的棋灵，最终抵达迷城核心揭开永动之谜。每一局都是平行时空中的一次尝试——死亡后记忆清零，但迷城会记住棋手的成长。

**2. 核心玩法（游戏循环）：**

- **探索（随机生成）：** 程序化生成多楼层地牢，每层包含战斗房、商店房、宝箱房、精英房、Boss房、事件房、休息房等多种房间类型，玩家在节点式路线上选择前进方向，战争迷雾遮蔽未探索区域。
- **战斗（回合制战棋）：** 网格地图上回合制对抗，每回合拥有固定行动点（AP），可用于移动、攻击、释放技能、使用道具。伤害基于攻防公式 + 暴击计算，地形和陷阱可被利用。
- **构筑（Build）：** 通过装备（武器/防具/饰品）、遗物（永久被动）、技能树升级、消耗品组合出独特流派，如"元素法师流""重装坦克流""远程风筝流""召唤流"等。
- **死亡与成长：** 局内永久死亡，进度清零；局外通过全局货币解锁新角色、新物品、新难度，形成"死一次更强一次"的循环。

**3. 美术风格：**

- **基调：** 暗黑奇幻像素风格，带有棋盘/几何纹样的视觉符号，呼应"棋局"主题。
- **色彩：** 主色调为深紫/暗蓝的地下城氛围，搭配各楼层主题色（地下城=灰褐、森林=墨绿、火山=橙红、冰原=青白），技能特效用高饱和色突出。
- **视角：** 俯视角 2D 网格，瓦片尺寸 32×32 像素，玩家始终位于屏幕中心区域。

**4. 游戏差异化创新：**

- **差异化1 — 空间战术维度：** 区别于杀戮尖塔的纯卡牌，网格战棋引入位置、朝向、地形、陷阱、可破坏障碍物等空间要素，每一步移动都是策略决策。
- **差异化2 — AI 行为树驱动：** 敌人不再是固定模式，行为树让 Boss 多阶段切换、精英召唤狂暴、敌人协同配合、适应性应对玩家策略（防风筝/防绕后）。
- **差异化3 — 多维 Build 组合：** 装备 + 遗物 + 技能树 + 地形互动四维组合，远比单一卡牌或单一装备的 Build 更丰富，套装效果和物品合成进一步扩展深度。

## 四、 游戏子系统设计 (Game Subsystems)

**1. 技能子系统：**

MVP 阶段 1 个角色，技能配置：
- **基础攻击：** 1.0× 倍率，消耗 1 AP，近战单体。
- **主动技能1：** 冲锋斩（1.5× 倍率，消耗 2 AP，突进+攻击）。
- **主动技能2：** 元素箭（1.8× 倍率，消耗 2 AP，远程单体）。
- **被动天赋（升级三选一，共 3 个节点）：**
  - 节点1：暴击率 +10%
  - 节点2：AP 上限 +1
  - 节点3：移动范围 +1

**2. 物品/道具系统：**

- **装备：** 武器（影响攻击力/攻击范围）、防具（影响防御）、饰品（特殊效果）。MVP 提供 3-5 件基础装备。
- **遗物/神器：** 永久被动加成，不可移除。MVP 提供 2-3 个遗物。
- **消耗品：** 药水（回血/增益）。MVP 提供 2 种药水（小红药、力量药）。
- **背包：** 5 格消耗品快捷栏 + 装备槽（武器/防具/饰品各 1）。

**3. 地牢生成系统（核心）：**

- **算法：** BSP 二叉空间分割 + 房间连接，生成房间+走廊式网格地图。
- **MVP 楼层：** 1 层，6 个房间（1 Boss + 1 商店 + 1 休息 + 3 战斗）。
- **房间最大尺寸：** 12×12 瓦片（384×384 像素）。
- **地图最大尺寸：** 40×40 瓦片。
- **战争迷雾：** 未探索区域不可见，已探索区域半透明显示。
- **随机种子：** 支持种子输入，可复现/分享同一局。

**4. 怪物/敌人系统（核心）：**

MVP 阶段 4 种敌人，由 AI 行为树驱动：
- **基础敌人1 — 史莱姆：** 低 HP、近战、慢速。行为树：巡逻 → 发现玩家 → 追击 → 攻击 → 撤退。
- **基础敌人2 — 骷髅：** 中 HP、远程攻击。行为树：保持距离 → 远程攻击 → 被近身时撤退。
- **精英敌人：** 高 HP、特殊技能（召唤小怪）、低血量狂暴。行为树：远程消耗 → 召唤 → 狂暴。
- **Boss：** 多阶段行为树。
  - 阶段1（100%-70%血量）：普通技能攻击。
  - 阶段2（70%-40%血量）：狂暴 + 召唤小怪。
  - 阶段3（40%-0血量）：全屏 AOE 技能。

**5. 城镇/NPC系统：**

本作无城镇系统，以 **休息房** 替代：恢复 30% 最大 HP、移除负面状态。商店房由神秘商人 NPC 经营，用本局货币购买装备/药水/遗物。

**6. 局外成长系统（核心）：**

- **全局货币：** 每局结算根据击杀数、楼层、成就获得"记忆碎片"。
- **解锁系统：** 用记忆碎片解锁新角色、新物品、新难度等级（MVP 仅实现货币记录，解锁内容第二阶段填充）。
- **永久死亡：** 角色死亡后局内进度清零，回主菜单。

**7. 数值与平衡管理：**

- **属性体系：** HP / ATK / DEF / 暴击率 / 暴击伤害 / AP上限 / 移动力。
- **伤害公式：** `最终伤害 = max(1, (ATK × 技能倍率 - DEF × 0.5)) × (暴击 ? 1.5 : 1.0)`
- **MVP 数值基线（后续调整）：**

| 属性 | 玩家初始值 | 史莱姆 | 骷髅 | 精英 | Boss |
|------|----------|--------|------|------|------|
| HP | 30 | 8 | 12 | 20 | 60 |
| ATK | 6 | 3 | 4 | 5 | 8 |
| DEF | 2 | 1 | 1 | 2 | 3 |
| AP | 5 | 3 | 3 | 4 | 4 |
| 移动 | 3 | 2 | 2 | 3 | 2 |
| 经验 | — | 5 | 8 | 20 | 100 |

- 暴击率：基础 10%，暴击伤害 1.5×。
- 元素系统：MVP 不实现，第二阶段加入。

**8. 任务与成就子系统：**

MVP 不实现，第三阶段加入。

## 五、 UED设计 (界面与体验)

**1. 主界面布局（HUD设计）：**

- **左上角：** 角色头像 + HP 条 + AP 条（行动点）+ 状态效果图标。
- **右上角：** 小地图（当前楼层缩略图，已探索区域）+ 楼层信息。
- **底部中央：** 物品快捷栏（药水/消耗品 1-5 号键位）。
- **底部右侧：** 背包按钮、技能面板按钮。
- **战斗时叠加：** 网格高亮显示可移动范围（蓝色）、攻击范围（红色）、技能范围（黄色）；敌人血条悬浮于头顶。

**2. 交互反馈：**

- **受击：** 屏幕四周红色闪烁 + 受击音效 + 角色短暂抖动（震动可开关）。
- **拾取：** 物品有"吸入"特效飞向角色，伴随清脆 UI 音效。
- **攻击反馈：** 命中时敌人闪白 + 伤害数字飘字（暴击为放大金色的伤害数字）+ 屏幕轻微震动。
- **移动反馈：** 网格高亮 + 角色平滑移动动画 + 落地音效。
- **技能释放：** 全屏特效 + 技能图标冷却动画 + 专属音效。
- **回合切换：** 顶部出现"你的回合"/"敌人回合"提示横幅，短暂淡入淡出。

**3. 游戏操作说明：**

- **鼠标左键：** 选择目标格/敌人/物品。
- **鼠标右键：** 取消选择/查看信息。
- **WASD / 方向键：** 移动角色（探索模式）。
- **1-5 数字键：** 使用对应快捷栏物品。
- **Q/E：** 释放技能 1/2。
- **空格：** 结束回合（战斗中）/确认（菜单）。
- **Tab：** 打开背包。
- **C：** 打开角色面板。
- **Esc：** 暂停菜单。
- **所有操作均支持鼠标点击替代**，适配无键盘场景。

## 六、 音效与音乐 (Audio)

**1. 背景音乐：**

- **主菜单：** 神秘悠远的弦乐 + 轻微电子合成，营造"古老棋局"氛围。
- **探索中：** 低沉氛围环境音，节奏缓慢。
- **战斗中：** 节奏加快的战鼓 + 弦乐，Boss 战加入合唱层。
- **商店/休息：** 轻松的拨弦乐器，缓解战斗紧张感。
- **死亡：** 渐弱的不和谐和弦。
- **胜利：** 主题旋律的昂扬变奏。

**2. 音效设计：**

- **移动：** 脚步声（随地形变化：石板/草地）。
- **攻击：** 挥砍/射箭/施法三类基础音效，按武器类型细分。
- **命中：** 金属碰撞/肉体撕裂。
- **暴击：** 加重的低频"轰"声 + 高频金属音叠加。
- **技能：** 每个技能独立音效。
- **UI：** 按钮点击、菜单切换、物品拾取、金币掉落等清脆短音。
- **敌人：** 史莱姆=黏液声、骷髅=骨头碰撞、Boss=低吼/咆哮。

## 设计决策

### 技术方案

- **架构选择：** 状态机驱动的主循环 + 模块化包结构（`core/world/entities/combat/ai/items/ui/states/utils`），模块依赖从底层往上单向流动。
- **关键组件：**
  - `core/game.py`：主循环 + 状态栈管理
  - `world/dungeon_generator.py`：BSP 算法地图生成
  - `combat/battle_manager.py`：回合制战斗状态机
  - `ai/behavior_tree.py`：行为树框架（Selector/Sequence/Condition/Action 节点）
  - `entities/`：实体系统（Entity 基类 → Player/Enemy 子类）
- **数据存储：** JSON 格式存档，`./saves/` 目录，单存档槽。局内（玩家位置、已探索房间、HP/AP、背包）+ 局外（全局货币、解锁状态）分离。
- **接口设计：** 模块间通过 Python import 通信，无外部 API；状态间通过 `game.push_state()`/`game.pop_state()` 切换。

### 约束条件

- **性能要求：** 目标 60 FPS，下限 30 FPS；地图生成 < 100ms；AI tick < 16ms。
- **兼容性：** Windows 10/11，Python 3.10+，pygame-ce 2.5.7。
- **分辨率：** 1280×720 窗口模式（MVP 不支持全屏切换）。
- **相机：** 跟随玩家，不支持边缘滚动。
- **可扩展性：** 模块化设计支持后续阶段增量添加（新角色、新楼层、新 AI、新物品均通过数据驱动扩展）。

### 风险评估

- **技术风险：** BSP 地图生成可能出现房间重叠/走廊断裂 → 需编写生成验证测试。AI 行为树复杂度增长可能导致 tick 超时 → 需限制每回合 AI 决策深度。
- **依赖风险：** pygame-ce 社区维护，版本更新可能引入兼容问题 → 锁定 2.5.7 版本。
- **进度风险：** 9 天 MVP 时间紧 → 严格按里程碑交付，每日 commit 保证进度可追溯，超时功能降级到第二阶段。
